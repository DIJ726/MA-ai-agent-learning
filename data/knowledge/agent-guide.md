# Agent 入门知识库（内部素材）

> 本文件作为 MCP Resource 的文本载体，供 Server 暴露给 Client 读取；后续也可作为 RAG 检索的语料。

## 1. 什么是 Agent

- Agent = 大模型 + 工具 + 记忆 + 循环决策。
- 典型决策范式是 ReAct：**Thought（思考）→ Action（行动/调工具）→ Observation（观察回填）**，循环直到信息足够给出 Final Answer。

## 2. MCP 是什么

- MCP（Model Context Protocol）是标准化「模型 ↔ 外部工具/数据」的协议，让 Agent 以统一方式调用外部能力。
- 三个角色：
  - **Host**：LLM 应用本体，是和用户对话的一方。
  - **Client**：住在 Host 里、说 MCP 协议的一侧。
  - **Server**：能力提供方，把工具/资源/提示暴露给 Client。

## 3. MCP 三种原语

- **Tool（工具）**：模型决定调用的动作函数（对应 HTTP POST），如查订单、做计算。
- **Resource（资源）**：应用决定喂进上下文的数据（对应 HTTP GET），如文件、知识库、接口响应。
- **Prompt（提示）**：用户按名字选用的可复用消息模板（类似斜杠命令）。

## 4. 工具调用基本约定

- 数值计算、日期推算必须走工具，不心算。
- 参数用结构化 JSON 传递；工具返回的结果回填为 Observation，供下一轮推理使用。
- 未知工具、参数异常应由调用方兜成错误说明，不中断整个循环。

## 5. 记忆

- **短期记忆**：对话历史滑动窗口，跨轮保留最近若干轮。
- **长期记忆**：把事实存入知识库，按相关性召回后补进上下文，供后续问答参考。

## 6. 常见边界

- Resource 是被动数据，不等同于可执行工具；要产生动作应注册为 Tool。
- Prompt 只负责组织消息模板，不直接访问数据库；需要数据时由 Tool 或 Resource 提供。
