# 学习笔记 · 周五 11/20 — 记忆：短期（对话）+ 长期（字典存）

> 第 3 周第 5 天。目标：给 ReAct Agent 加独立记忆模块。短期记当前会话对话（滑动窗口），长期记可跨会话复用的事实（字典存 + 按相关性召回）。对应计划条目：「记忆：短期（对话）+ 长期（向量存），给 Agent 加简单 memory 字典」。

---

## 一、Agent 为什么需要记忆

- **没有记忆**：每轮对话都是全新上下文，模型不知道上一轮聊过什么，也记不住用户的偏好/背景。
- **短期记忆**：覆盖「当前这一次会话」的多轮问答，超出窗口的旧对话丢弃。
- **长期记忆**：覆盖「跨会话」的稳定事实（偏好、项目背景、配置），新对话开始时按问题相关度取回一部分塞进上下文。

## 二、两层记忆的分工

| 层级 | 类 | 存什么 | 生命周期 | 检索方式 |
|------|----|--------|----------|----------|
| 短期 | `ShortTermMemory` | user / assistant 对话消息 | 当前会话，滑动窗口 `max_turns` 轮 | 不检索，整体取最近若干条进 messages |
| 长期 | `LongTermMemory` | 事实条目（正文 + 标签 + 时间 + 命中次数） | 跨会话，可 JSON 落盘 | 词袋 Jaccard 相似度，召回 top-k |
| 门面 | `AgentMemory` | 组合上面两者，对外统一入口 | —— | `remember_conversation` / `remember_fact` / `recall_relevant` |

## 三、`memory.py` 结构

### 3.1 数据条目 `MemoryEntry`（dataclass）
- `role`：`user` / `assistant` / `fact`
- `content`：正文
- `created_at`：写入时间
- `tags`：主题标签
- `access_count`：被召回命中次数（后续可做重要性排序，本周只记录）
- 提供 `to_dict` / `from_dict` 用于 JSON 落盘往返。

### 3.2 短期 `ShortTermMemory`
- `add(role, content, tags)` / `add_user` / `add_assistant`
- `to_messages()`：组装 OpenAI 格式消息；只留最近 `2 * max_turns` 条；截断后首条若是 assistant 则丢弃，保证序列从 user 开始。
- `recent_text()`：拼纯文本，调试用；`__len__` / `clear`。

### 3.3 长期 `LongTermMemory`
- `save(fact, tags) -> id`：存一条事实，返回 `mem-0001` 形式的 id；空正文忽略。
- `search(query, top_k)`：按相似度召回，返回 `[(id, entry, score), ...]`，命中条目 `access_count +1`；相似度为 0 不返回。
- `recall_text(query, top_k)`：拼成给模型看的文本；无结果返回空串。
- `get(id)` / `forget(id)` / `clear`。
- `store_path` 传入时写本地 JSON；纯内存模式（None）不碰文件。文件损坏时按空记忆处理，不崩。

### 3.4 门面 `AgentMemory`
- `remember_conversation(user, assistant)`：一轮问答进短期。
- `remember_fact(fact, tags)`：事实进长期。
- `recall_relevant(query)`：长期召回文本。
- `clear()`：两层一起清。

## 四、长期检索：词袋 + Jaccard（向量检索雏形）

本周不引入 embedding 模型和向量库（那是第 6 周 RAG），先用最朴素的方式把「存事实 → 按相关性取出」跑通：

1. **分词（`_tokenize`）**：英文/数字按词切；中文按单字 + 相邻二字组，组成 token 集合。
2. **相似度（`_jaccard`）**：`交集大小 / 并集大小`；查询词袋与条目正文、标签分别算，取较高值。
3. **排序**：按相似度从高到低取 top-k。

局限（刻意保留，留给后续周次）：
- 词袋不理解同义/近义（「学习」和「上课」匹配不上）；第 6 周用 embedding 稠密向量替代。
- 纯关键词粗召回，可能带回只沾一个字的条目；线上场景需要重排。

## 五、接入 `min_agent.py` 的数据流

`ReActAgent` 新增 `memory` 参数（默认新建 `AgentMemory()`）。`run(question)` 流程：

```
question
  → memory.recall_relevant(question)        # 长期召回相关事实
  → 召回非空则拼进 system 提示（"已知长期记忆…"）
  → messages = system + 短期历史 + 当前 user 问题
  → ReAct 循环（调模型 / 解析 / 工具执行 / 观察回填）
  → 最终回答写入短期记忆（user 问 + assistant 答）
```

同一 Agent 实例连续多轮 `run`，短期历史自动带到下一轮；长期事实跨会话保留。

## 六、自测结果（离线，不耗真实 token）

- **短期滑动窗口**：`max_turns=2`，写入 4 轮后只保留最近 2 轮 4 条，序列从 user 开始。
- **长期召回**：存入作息/项目/配置三条，query「晚上一般几点学习」正确命中作息条目（top score 0.24）；query「学习计划是什么」召回项目条目。
- **JSON 落盘往返**：新实例从文件读回，条目正文/标签完整。
- **组合门面**：问答入短期（2 条），事实入长期并可被召回。
- **Agent 接入回归**：同一 Agent 跑两轮，短期留下 4 条；第一轮长期召回进系统上下文，第二轮短期历史仍在；原有计算器/时间/未知工具用例全部通过。

## 七、边界与后续排期

- **真实向量检索（W6）**：接 embedding 模型 + Chroma/FAISS，替换词袋 Jaccard；本条目的词袋实现作为原理演示。
- **自动事实抽取**：当前由调用方显式 `remember_fact`；后续可让模型从对话里提炼稳定事实再写入长期记忆。
- **长期记忆落盘文件**：本周默认纯内存；需要跨会话持久化时给 `AgentMemory` 传 `long_store_path`，JSON 自动读写。
- **周六**：接真实 LLM 端到端跑通并调试（模型跳过工具、Action Input 混入 Thought 两个已知问题）。

## 八、易混点 / 面试话术

- **短期 ≠ 长期**：短期是会话内滑动窗口，过期即弃；长期是跨会话事实，按相关度按需取回，不整体塞进上下文。
- **召回而非全量**：长期记忆只把和当前问题最相关的几条放进提示，避免上下文越长越乱、token 越花越多。
- **记忆是外挂，不是推理**：Agent 仍走 ReAct 循环；记忆只负责提供已知背景，工具执行和决策逻辑不变。
