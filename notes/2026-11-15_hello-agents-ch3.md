## 一、Transformer 与注意力（概念层面）

- **Transformer**：当前大模型的基础网络结构（2017 年论文《Attention Is All You Need》），核心是 **自注意力机制（Self-Attention）**。
- 注意力作用：模型在处理一个词时，能"看到"句子里其他词并分配不同权重。例如"苹果发布了新手机"里的"苹果"，注意力会把它和"手机"关联，而不是和水果关联。
- **编码—解码 / 上下文**：模型把输入文本转成向量序列，逐层计算注意力，最后解码出输出 token。我们不需要手推数学，记住三点即可：
  1. 输入是一串 token（词元），输出也是一串 token；
  2. 每个 token 都能关注上下文里的其他 token；
  3. 并行计算是大模型能规模化训练的基础。

## 二、提示（Prompt）与消息结构

### 2.1 OpenAI / 千问兼容消息格式（我们项目一直在用）
| 角色 role | 作用 | 谁写 |
|-----------|------|------|
| `system` | 人设、规则、输出格式，最靠前 | 程序固定 |
| `user` | 用户输入 | 用户 |
| `assistant` | 模型上一轮回答 | 程序存进历史 |

### 2.2 提示工程要点（前几周已实践）
- **角色与约束写进 system**：例如"只输出 JSON""始终用简体中文"。
- **给清上下文**：日期、城市、示例、格式要求，缺什么模型就猜什么。
- **采样温度 temperature**：0 偏确定，高值更发散；结构化输出用低温（0.2–0.3），创意用中高温。
- **结构化输出**：`response_format=json_object`（JSON mode）+ 解析重试 + 降级纯文本（见 `chat_json`）。
- **Few-shot 示例**：在 prompt 里给一两个输入输出样例，模型更容易照格式作答。

| 系列 | 代表 | 特点 |

| OpenAI GPT | GPT-5 / o 系列 | 综合能力强，生态成熟 |

## 四、LLM 的局限（为什么 Agent 需要外挂能力）

这是本章最关键的一节——**局限正好对应 Agent 要补的组件**：

| 局限 | 表现 | Agent 的对策（对应第 3 周内容） |
|------|------|-------------------------------|
| **幻觉** | 会编造看似合理但错误的事实 | 工具调用取真实数据 + 反思校验 |
| **无长期记忆** | 每次调用无状态，不记得上轮 | 对话历史 / 向量库记忆 |
| **上下文窗口有限** | 太长塞不下、注意力衰减 | 滑动窗口、摘要、RAG 检索 |
| **知识截止** | 只知道训练截止前的信息 | 联网搜索、外部工具取最新数据 |
| **不能直接操作外部世界** | 只会输出文本，不能查数据库/跑代码 | Function Calling / MCP 工具 |
| **推理不一定可靠** | 多步逻辑可能跳步、算错 | ReAct 循环分步执行 + 观察校验 + 重试 |
| **概率生成** | 输出是采样出来的，不稳定 | 低温、约束格式、重试与降级 |

## 五、对照本项目的呼应关系

- `chat_with_llm.py`：`temperature`、JSON mode、usage、`Conversation` 历史——都是本章"提示 + 局限对策"的具体实现。
- `token_cost.py`：上下文窗口和成本直接相关（输入 token 随历史线性增长）。
- 天气助手：用 LLM 生成自然语言建议，城市/日期由 JSON 结构化抽取——用结构化输出压制幻觉和格式漂移。

## 六、一句话总结
> 大模型是"有语言推理能力但失忆、不能动手、会幻觉"的发动机；Agent 给它配上记忆、工具和规划循环，才变成能完成任务的系统。
